# Candidate CLI/output compatibility

The sole token/argument inventory is [commands.json](../spec/catalog/commands.json).
`source/command_help.inc` is generated by `python tools/command_help.py`; CI checks
its correspondence. These are development contracts for 0.4.0-beta.3, not an
announcement of stable API support.

## Preserved and deliberate compatibility changes

- No arguments requests TUI. Redirected input/output does not silently choose it.
- NTop `-d` is dump. `--delay` is 1..600 deciseconds; `--interval` is 50..60000
  milliseconds. Later duplicate interval choices win; no keymap changes the grammar.
- `--snapshot`, `--dump` and `-d` share one snapshot mode. Format alone selects it.
- Long argument options accept `--option=value`. A final `--` is accepted; positional
  operands outside query/inspect/log still fail. Unknown tokens are not shell text.
- Metadata/help/version remain JSON schema 1. Snapshots/query/inspect/log use
  schema 2; the old `cpu_share` is removed in favor of named `cpu_percent`
  normalization. Settings migrate independently to schema 2 on explicit save.
- Query system/services reject process-only selectors. Inspect takes exactly one
  PID and rejects extra process selectors. Empty inspect emits an empty typed
  result with exit 3. The private provider-worker invocation is not a public CLI.

## Schema 2 structure

| Field | Meaning/type |
| --- | --- |
| `schema`, `version`, `profile`, `command` | Schema integer 2, product/profile strings, snapshot/query/inspect/log |
| `inspect_pid` | Requested PID, or zero outside inspect |
| `cpu_normalization`, `cpu_active_capacity` | `one-core` or `active-machine-capacity`, observed capacity or null |
| `sample` | Sequence, clock, collection start/observe/publish/read times, age/status, requested cadence, completeness and observed/selected/unresolved-filter counts |
| `system` | CPU provider scope/timestamps and typed CPU/capacity/physical-memory/commit/uptime values |
| `tree` | Enabled state, unresolved-parent count and index-allocation fallback; unknown chronology remains roots |
| `processes` | PID/parent/thread/base-priority/name/lifetime, per-process observation times, typed CPU/memory/I/O/age and owner identity |
| `providers` | Only explicitly requested command_line/services/per_core/image_path/threads/affinity objects; ordinary snapshots do not request them |
| `text_encoding_loss` | True if malformed native Unicode required replacement during serialization |

Metric objects have `status`, `unit`, `value`. Status is valid, denied,
unsupported, warming_up, reset, error, capacity or stale. Only valid measurements
carry a numeric value; other measurements carry null. Exact 64-bit integers and
raw tick/FILETIME/sequence values are decimal strings. `sample_elapsed_ms` is a
numeric elapsed duration retained for compatibility. Percent/rate/elapsed-width
values are finite JSON numbers; PID/count/priority are bounded JSON integers.
Times named `*_ms` with the GetTickCount64 clock are boot-relative, not UTC.
FILETIME creation values are 100 ns units in the Windows epoch. Names and strings
are JSON escaped; no terminal escape interpretation is intended.

`owner.value` and `owner.sid` are SID strings or null. Optional account-name lookup
has its own status, observation time and string; a stale cached name is explicitly
marked stale. An unknown name does not invalidate an observed SID. Windows base
priority/class semantics are not Unix nice. Process I/O means process transfers,
not device attribution. The metric catalog owns detailed units/definitions.

## Provider diagnostics

Every requested provider reports status, numeric error domain/code, actual worker
start/observe times, elapsed/acquisition milliseconds, `response_received`,
`retirement_confirmed`, identity, returned count, observed total count and value.
Response validation does not prove worker retirement. Zero observation time means
no observation was obtained, not a sample taken at boot. Capacity can contain a
partial array, with count/total and the capacity status retained.

Error-domain numbers are 0 none, 1 Win32, 2 HRESULT, 3 PDH, 4 worker exit code.
They qualify the meaning of `native_error`; a nonzero number is not blindly
translated as GetLastError. Provider statuses additionally include unavailable,
timeout, cancelled, protocol_error, identity_changed, identity_unavailable,
retirement_pending and admission_closed. Service state numbers retain Windows SCM
values; a PID association includes its separately checked creation identity.
Per-core rows retain original PDH instance/group/index and their individual state;
legacy processor scope is identified instead of claiming processor-group parity.

Providers and baseline samples have different observation times. Consumers must
use those times when evaluating age, rather than treating stdout write time as a
new hardware observation. Per-core TUI data visibly ages; native CLI output retains
provider measurement and timing instead of silently refreshing cached values.

## Exit and stream behavior

| Exit | Meaning |
| --- | --- |
| 0 | Completed requested operation under the command's declared scope |
| 1 | Runtime/output/configuration failure |
| 2 | Invalid, conflicting or explicitly unavailable invocation |
| 3 | Explicit partial/provider/capacity condition, or requested inspect target absent |
| 124 | Emergency own-monitor shutdown because owned work did not retire in grace |
| 130 | Cooperative cancellation |

Individual denied process fields remain explicit without making every ordinary
snapshot a failed command. Requested optional provider failure produces exit 3.
Output is stdout, diagnostics stderr. `log` is JSON Lines, requires explicit output
and count/duration, refuses existing destinations and applies its byte cap to
complete delivered records. It does not install a background service. Known waits
respect remaining duration; arbitrary native/file/pipe calls have no promised hard
wall-time deadline. Broken output is failure, not successful completion.

## Beta 3 additive inspection fields

`inspect PID --image-path --threads --affinity` adds optional provider objects to
schema 2. Each flag requires inspect; none implies command-line collection.
Affinity only reads and rejects an =MASK value. TUI mutation uses explicit review.

`image_path.value` is the full executable path or null; its field state is retained
in the provider wrapper. `threads.value` contains at most 1,024 records with
integer tid/pid, identity_status/times_status/priority_status and corresponding
Win32 error fields, nullable decimal-string creation_filetime/kernel_100ns/
user_100ns, nullable integer relative priority, and decimal-string observed_ms.
Execution counters are lifetime 100 ns units, not sampled CPU percentages. The
containing provider retains process creation identity, totals/capacity, timing
and retirement evidence. A TID without creation identity is not a safe target.

`affinity.value` has status/error_domain/native_error, mask_bits, group,
process_group_count, system_group_count, limitation and nullable process_mask/
system_mask. Valid masks are exact strings such as `"0x0000000000000003"`, never
lossy JSON numbers. Multiple groups and unrepresentable 32-bit native scopes
explicitly report unsupported. Existing aliases, provider meanings and schema-2
fields remain compatible; the new fields are opt-in additions.
